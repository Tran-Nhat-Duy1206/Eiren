## Evidence boundaries

A green CI cold migrate and synthetic restore proves repeatability of **this** migration set and basic schema/constraint access on a disposable database; it does not establish a secure encrypted/off-host production backup, operator recovery point/time, deletion replay, readiness, deployment TLS/reverse proxy, native Windows signal delivery, real Discord sends, human OAuth mutations, AI provider traffic or privacy-law compliance. Current `/healthz` is liveness only. V8.2 data-policy authority/windows/holds and V8.6 operational recovery remain unapproved; V8.5 presentation remains unimplemented. Do not reinterpret an absent real-user test as a pass.

## V8.2 — Closed private-content lifecycle (new evidence; V8.1 observations above remain historical)

**Baseline:** main `e00cdf55ce0fd9f8bce501df4666cebe5de3755f`; branch `feature/v8-private-lifecycle`. V8.2 approval now **supersedes only** the V8.1 statement that ticket/report/appeal retention authority/windows/holds were unapproved. V8.3 user-request erasure, V8.4 readiness, V8.5 UI redesign and V8.6 operator recovery remain outside this branch.

**Approved policy:** actual GUILD_OWNER-only enable/change/disable/hold; ADMIN-safe metadata view only; OFF for old and new guilds; owner preview → exact confirmation required. Defaults and owner ranges: ticket 90 days (30–365) from `closed_at`, closed report 365 (90–730) from `closed_at`, reviewed appeal 365 (90–730) from `reviewed_at`, using PostgreSQL time. No moderation cases, notes, suggestions or other unrelated domains. Holds have no expiry. Receipts contain metadata only and expire after 730 days. DB-only means Discord copies/exports/replicas/old backups are unaffected. No actual guild data or live user payload is authorized for tests.
