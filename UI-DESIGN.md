# V8.5 presentation contract

## Scope and principles
Presentation only: calm, compact, technical administration UI. Existing routes, queries, authorization, state machines, component identities, public/ephemeral visibility, leases and mutation confirmations remain authoritative. No migration/dependency/framework, dashboard JavaScript, remote asset, theme switch, localization, provider, repair control or V8.6 work. Dark/system-font default. No WCAG certification claim.

## Official Eiren visual identity — approved follow-up

Brand: **Eiren**. Primary palette: **Black + Purple**. Premium, technical, elegant and controlled—not RGB/cyberpunk overload or purple on every surface. Near-black environment, deep violet surfaces, purple accent, violet gradients, restrained glow, subtle lighting and original geometric SVG. Technical lines/nodes/orbits may support one coherent abstract geometric E/orbit mark; content remains dominant.

Final foundation tokens: --bg #08080d, --surface #11101a, --surface-raised #191526, --surface-muted #0d0c13; muted violet-gray borders, soft near-white text and lavender-gray secondary text. Brand family: deep violet #5b21b6, violet #6d28d9, primary #7c3aed, bright #8b5cf6, soft #a78bfa, light #c4b5fd. Shared --gradient-brand, --gradient-brand-subtle, --gradient-surface, --glow-purple and --glow-purple-strong centralize effects. White CTA text uses contrast-safe darker gradient stops; check every stop, not just the darkest. INFO is purple; SUCCESS green, WARNING amber/gold, DANGER red and NEUTRAL gray/lavender. UNCERTAIN stays ambiguous warning, not INFO/Failed; its dashed amber badge border distinguishes it from ordinary solid-border Pending without changing mapping.

Gradients are deliberate: primary CTA, current navigation, restrained Login/picker surfaces and interactions. The original mark uses static purple geometry; page headers and metrics use quiet solid violet edge accents. Background atmosphere uses low-opacity static purple radial gradients over black; no heavy blur/backdrop-filter or bitmap. Normal panels/tables stay quiet dark layers with modest violet-gray borders/shadows, not all glowing. Functional warnings/errors outrank branding. Primary gradient CTA has restrained hover lighting/lift; disabled controls lose glow/lift. Secondary dark surfaces remain distinct; danger controls remain red. Violet/lavender keyboard focus is stronger than decorative glow.

Motion: **CSS-only**, subtle 120–220ms interaction transitions; never continuous/infinite animation or decorative movement on static panels. prefers-reduced-motion: reduce disables unnecessary transitions/transforms; static gradients/glows/SVG may remain. At <=48rem reduce atmosphere and mark size; no overlap, page overflow or lost confirmation/focus at narrow/200% reflow.

SVG: **trusted first-party static source-controlled markup/assets only**, original geometric E/orbit mark and one lightweight empty-state visual. No script, foreignObject, event attributes, javascript:, external href, remote content/images/styles or user/guild/status/ID interpolation. Adjacent Eiren text makes the mark decorative: aria-hidden=true, focusable=false. Mark appears in shell header and compact Login. Current selective empty art appears only in the no-manageable-guilds picker state, never every empty table. No SVG rendering/conversion dependencies or Discord SVG images.

Login is the strongest compact identity expression: black/purple ambient glow, original mark, refined dark authentication panel, thin brand accent and gradient CTA—no marketing landing page. Guild entries are compact interactive raised dark surfaces with violet hover/focus edges; no invented icons or extra fetch/query. Shell/current-nav/page headers receive subtle violet accents; existing navigation structure/landmarks/content stay intact.

Discord: purple identity for neutral/INFO/configuration presentation (INFO #8b5cf6); semantic success/warning/error/uncertain/disabled colors remain. Rich status titles retain mandatory readable labels, optionally restrained Unicode symbols; short confirmations remain plain text. Structured configuration/staff/public summaries may gain concise hierarchy and restrained already-authorized metadata/footer. No user narrative rewriting, extra disclosure, changed public/ephemeral/mentions/custom IDs/retry semantics or giveaway result lookup prefix. Dashboard-first SVG only; no fake CSS effects in Discord.

Validate contrast programmatically for body/bg, muted/surface, primary text/all gradient stops, danger text/surface and focus/bg (practical 4.5 text/3 nontext minimums, not WCAG certification), static SVG safety, theme/gradient/radial/reduced-motion contract, semantic separation and all existing compatibility gates. Inspect fresh synthetic desktop/narrow/reflow screenshots, revise only visual defects, and record the 15 user visual-review questions in the validation follow-up. Full original units/DB/restore/runtime/privacy gates and new exact-head CI remain required; no PR or V8.6.

## Dashboard tokens and hierarchy (V8.5A–C)
Use CSS custom properties: `--bg`, `--surface`, `--surface-raised`, `--surface-muted`, `--text`, `--text-muted`, `--border`, `--border-strong`, `--accent`, `--focus`; semantic `--success`, `--warning`, `--danger`, `--info`, `--neutral` with subtle corresponding surface tokens. Text is always readable without color. Muted text must retain contrast; borders and a visible focus outline convey interaction/state independently of hue.

Spacing: `--space-1` .25rem, `--space-2` .5rem, `--space-3` .75rem, `--space-4` 1rem, `--space-5` 1.25rem, `--space-6` 1.5rem, `--space-8` 2rem. Restrained type scale: metadata .8125rem, small .875rem, body 1rem, subheading 1.125rem, section 1.25rem, title 1.75rem. System UI fonts; technical IDs use ui-monospace/SFMono-Regular/Consolas/monospace. Modest radii and borders. The user-approved black/purple identity above supersedes the initial conservative prohibition of decorative gradients, animation and shadows: restrained purposeful effects are approved, never mandatory for understanding state.

Shared escaped SSR primitives live in `src/dashboard/presentation.ts`: statusBadge, notice, emptyState, panel, metadataList, tableShell, fieldHelp, formGroup, destructiveWarning, pageHeader. All data/text/attribute arguments are escaped; explicitly named HTML body slots accept only composed, already-escaped renderer markup, never raw domain content. Helpers are not a template framework and never automatically serialize unknown Error.

Status tones SUCCESS/WARNING/DANGER/NEUTRAL/INFO cover Enabled, Disabled, Active, Pending, Running, Succeeded, Failed, Skipped, Uncertain, Closed, Open, Under Review, Accepted, Rejected, Implemented and existing governance/operational states. Disabled is neutral, not failed; Pending differs from Running; Accepted differs from Rejected. Uncertain uses WARNING, never generic Failed. Unknown external labels remain escaped neutral text. NOT_TRACKED/UNAVAILABLE are not successful/zero/resolved. Avoid badges for ordinary non-status values.

## Shell and navigation (V8.5B)
One header/nav/main/footer, one main landmark and a visible-on-focus skip link targeting `#main`. Header shows Eiren, escaped server/page context, secondary access metadata and ordinary logout. Each page has one h1, concise optional description; no repeated oversized server headings. Login/picker have a centered single-column shell. Main content has a restrained maximum width and min-width:0.

Grouped navigation: General (Overview/Members), Moderation (Moderation/Roles/Tickets/Suggestions), Community (Levels/Events/Giveaways/Analytics), Automation (Automations), Governance (Data retention/Privacy requests/Operations), System (Bot Settings). Preserve existing access filtering exactly. Current page has aria-current="page", weight and border/background. At/below 48rem the sidebar becomes horizontally scrollable groups with an explicit scroll hint; links stack within each group. Navigation remains keyboard accessible without a script or hidden menu; targets at least 44 CSS pixels.

## Components, forms and safety (V8.5C)
Panels separate real sections/settings/warnings, not every sentence. Overview uses existing count data only as compact labeled metrics; no new queries/trends. Tables retain headings/captions, wrapping and explicit focusable overflow regions; no page-level horizontal overflow. IDs are secondary metadata and remain available. Contextual empty states describe missing data without inventing actions. No invisible critical-text truncation.

Every visible form control has a visible explicit/wrapping label. Added help associates with aria-describedby and document-unique IDs; hidden CSRF/state inputs remain hidden. Preserve names/routes/values/native validation and owner/ADMIN conditions. Primary = ordinary main/save action; secondary/subtle = supporting action; danger = consequential destructive control. Existing checkbox/phrase requirements stay byte-for-byte semantically identical. Warnings describe consequences in text; no extra business confirmations.

Success feedback, if implemented, uses only server-controlled fixed allowlisted notice keys and PRG, never arbitrary query text/session flash storage. Unknown keys are ignored. Safe errors retain request IDs and sanitized text, role=alert; ordinary notices use role=status. CSP stays script-src 'none', with no inline scripts/event handlers/javascript URLs or remote CSS/fonts/images.

Automation Uncertain: “The external side effect cannot be proven. Do not blindly retry; inspect and reconcile.” Existing guarded reconciliation only. Governance gaps: committed domain mutation, normal audit unconfirmed; never repeat the mutation. Retention warnings explicitly say database-only redaction and surviving Discord copies/downloads/screenshots/backups. Privacy separates Erase eligible from Retained, states point-in-time scope/accountability/external copies/future activity. Operations prominently states Since process restart and four NOT_TRACKED boundaries; existing links only, no action forms/repair controls.

## Responsive/accessibility validation
CSS explicitly handles wide1280+, standard1024, tablet768 and narrow375–430 layouts. Forms/actions wrap and fit; tables scroll independently with visible affordance. No fixed-height clipping, focus traps, hover-only meaning or tiny controls. Review 200% zoom/reflow-equivalent viewports for Overview/Automations/Operations/Settings. Static tests cover landmarks/labels/IDs/headings/status roles/escaping/no JS; they are practical regression checks, not full accessibility certification. Synthetic desktop/narrow/zoom screenshots and real layout measurements are reviewed outside Git; do not use private guild data.

## Discord presentation (V8.5D–E)
Shared helpers live in `src/core/presentation/`, separate from dashboard and domain persistence. Semantic kinds: SUCCESS, INFO, WARNING, ERROR, UNCERTAIN, DISABLED. Small restrained color map; meaning always appears in text/title. Short confirmations remain plain text; appropriate summaries/announcements use bounded embeds with concise titles/descriptions/fields and secondary operational IDs. No raw Error formatter; upstream dispatcher/component sanitizer remains authoritative.

Keep original safe user-generated text and authorized fields, destinations, allowed-mention intent and public/ephemeral flags. Generated status/config/error output is non-pinging where safe; intentional existing ping behavior must be preserved and tested. Persistent verification/role/suggestion/event/giveaway custom/option IDs remain identical; edits/adoption use the same message/component schema. Button verbs remain domain-consistent; Primary main positive, Secondary neutral, Success affirmative opt-in, Danger genuinely consequential removal/cancel. No new action/workflow.

Discord timestamps use floor(source epoch milliseconds/1000), F or R style, without timezone shifting. Dashboard timestamps explicitly label UTC; configured guild timezone is a label only unless existing calculation uses it. Bound content2000, title256, description4096, field count25/name256/value1024, footer2048 and total embed6000; enforce component limits without altering valid existing IDs. Do not rewrite user narrative, suggestion content, prize or Automation static message. Preserve explicit “Content redacted by retention policy.” and never regenerate redacted content. UNCERTAIN always means outcome unproven/no blind retry/inspect-reconcile, not “try again”.
