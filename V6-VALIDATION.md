## Scheduler maintenance incident (2026-09-27 UTC)

A bounded pre-fix bot run reached **Dashboard listening on 127.0.0.1:3000** and **Discord gateway ready**, then emitted `job="analytics"`, `errorType="Error"`, `msg="V5 scheduled reconciliation failed"` on its first scheduled pass; the process was stopped. Directly invoking real PostgreSQL `analytics.runDue()` with a one-row-per-table cap isolated **`analytics_guild_hourly`** (SQLSTATE **42883**, `timestamp with time zone < interval`), before session cleanup or guild voice work. The retention SQL passed `now` as an untyped PostgreSQL parameter in timestamp-minus-interval expressions. PostgreSQL inferred an interval for the parameter, producing an invalid comparison with the `timestamptz` bucket column. The same defect affected the three hourly tables, member-state expiry and active-voice expiry; the first failing SQL was guild-hourly because the job processes tables sequentially. All three `now` expressions now explicitly cast to `timestamptz`. The existing per-guild `COALESCE` retention fallback was preserved. No development data was deleted to mask the fault.

Scheduler errors now report a fixed, sanitized stage and the version-neutral **Scheduled reconciliation failed** message, without SQL, error messages, environment values, tokens or cookies. Analytics success is logged only at debug level with the job name. Unit coverage checks staged, secret-free logging; `pnpm db:v6` executes the real six-table cleanup in a rollback-only fixture and checks zero-expired, live and expired dashboard sessions. Direct database checks found zero existing dashboard sessions, passed all three `cleanupExpired` cases, and confirmed development-guild analytics is disabled; scheduled voice work therefore skips that guild. A live voice snapshot with participants was not attempted.

## Guild-picker navigation incident (2026-09-27 UTC)

The human tester first completed real Discord OAuth and reached `/guilds`, but clicking **Open dashboard** returned Fastify 404 (`Route GET:/g/<guildId> not found`). `renderGuildPicker()` linked to `/g/:guildId` while the only registered page route is `GET /g/:guildId/:page`. The picker now links directly to `/g/:guildId/overview`; no unauthenticated redirect or duplicate authorization path was introduced. Two focused regression tests failed before the change and passed afterward: rendered links require `/overview`; the destination still requires a session and `DashboardAccess`, including denial of a forged foreign guild ID.

After `pnpm typecheck`, `pnpm test` (**280/280**), `pnpm db:v6` (**27 assertions**), `pnpm dashboard:check` and `pnpm build` passed, a bounded `pnpm dev` run reported Discord gateway ready and dashboard listening on `127.0.0.1:3000`; unauthenticated `/healthz` returned 200. During its three-minute auto-stop window, the **human tester reported** that clicking **Open dashboard** loaded Overview and that Analytics and Bot Settings both loaded. The process tree stopped and port 3000 had zero listeners. The tester reported **no authenticated mutation**; analytics settings were not changed or restored, and mutation behavior must not be claimed as browser-verified. An existing authenticated session could be reused; a second OAuth authorization was not required or claimed.
